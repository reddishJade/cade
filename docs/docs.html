Cade 设计理念与核心架构Cade Philosophy & Architecture

彻底摒弃失真的模型自我递归摘要，以不可篡改的无损历史与动态投影为基石。在 95% 上下文容量平滑换窗，借持久记忆跨越会话，原生驱动 TUI、CLI 与 Web 三端工作台。Abandoning lossy recursive self-summaries. Grounded in lossless event history, dynamic projections, zero-loss 95% context rollover, and durable memory across native TUI, CLI, and Web workbenches.

三大核心技术支柱Three Core Architectural Pillars

主流自治 Coding Agent 在面对长程复杂任务时，往往因周期性递归自我总结而遗失精细行号与堆栈细节，进而产生严重的幻觉累积。Cade 采用确定性状态机与事件流，确立了面向真实工业级代码库的三大核心支柱：Mainstream autonomous coding agents frequently lose precise line numbers and stack traces through periodic recursive self-summarization, compounding hallucinations over time. Cade establishes three deterministic pillars built for real-world engineering:

无损历史与动态投影Lossless History & Projections Pillar 1

会话以不可篡改的追加型日志（Append-only Event Log）持久记录，任何历史状态均可投影视角，支持毫秒级原子撤销（/undo），决不静默截断。Sessions persist as append-only event logs with dynamic projections. Snapshot pooling enables atomic file reverts and window rewinds without silent truncation.

95% 无摘要平滑换窗95% Summary-Free Rollover Pillar 2

当上下文触达窗口阈值（默认 95%）时，系统自动对冲冗余并无损继承核心任务目标，彻底摆脱模型自我总结带来的信息衰减与幻觉蔓延。Automatically rolls over context at 95% capacity, inheriting core goals while purging intermediate tool outputs, preventing degradation from heuristic summaries.

按需 MemoryOn-Demand Memory Pillar 3

昂贵经验保存为 workspace Markdown，按需使用既有工具搜索、沿原始 History 来源核验；正常 turn 和恢复不加载 Memory。Costly findings live in workspace Markdown, searched with existing tools and checked against original history. Normal turns and resume do not load Memory.

系统数据流与工作流模型System Data Flow & Workflow Model

在 Cade 中，任何交互请求均流经统一的运行时内核。内核负责安全沙箱门禁、工具调用并发分区以及事件历史的原子追加：In Cade, every interaction flows through a single unified runtime kernel responsible for sandbox policy gating, tool concurrency partitioning, and atomic event append:

设计不变量 (Core Invariants)Core Invariants

  • 确定性高于启发式：关键状态决策（如换窗、权限审查与回滚）由确定性代码判定，绝不依赖大模型的不稳定推断；Determinism over Heuristics: Critical lifecycle decisions (rollover, policy gating, reverts) are governed by deterministic algorithms, never left to LLM hallucinations;
  • 真实代码库安全隔离：严格限制文件读写边界于工作区内，高危操作强制触发人类在环（HITL）确认；Sandbox Path Jailing: Strict path boundaries jail read/write operations to the workspace, with high-risk operations gated by HITL approvals;
  • 全终端对等契约：TUI、CLI 与 Web 端完全基于同一套事件模型与工具集，保证跨端行为 100% 一致。Interface Parity: TUI, CLI, and Web share identical event models and toolsets, guaranteeing 100% behavioral parity.

安装与环境准备Installation & Prerequisites

Cade 需要 Python 3.12 或更高版本。推荐使用现代化包管理工具 uv 进行隔离安装与极速执行。Cade requires Python 3.12 or newer. We strongly recommend using the modern uv package manager for isolated global installations and instant execution.

环境依赖检查System Prerequisites

在安装 Cade 前，请确保你的系统满足以下基础环境：Before installing Cade, ensure your operating system meets the following prerequisites:

  • Python：3.12.0 或更高版本；Python: Version 3.12.0 or higher;
  • 操作系统：Linux (Ubuntu 20.04+, Debian 11+, Arch, Fedora), macOS 12+, 或 Windows 10/11 (推荐 WSL2)；Operating System: Linux (Ubuntu 20.04+, Debian 11+, Arch, Fedora), macOS 12+, or Windows 10/11 (WSL2 recommended);
  • Git：用于代码仓库上下文感知与版本快照回溯；Git: Required for repository context awareness and snapshot tracing;
  • Bubblewrap (可选但推荐)：Linux 下若启用沙箱隔离，建议安装 bubblewrap (Ubuntu/Debian: sudo apt install bubblewrap)。Bubblewrap (Optional but Recommended): On Linux, install bubblewrap for containerized sandbox isolation (Ubuntu/Debian: sudo apt install bubblewrap).

核心支柱 1：无损历史与动态投影 (/undo)Core Pillar 1: Lossless History & Dynamic Projections

拒绝破坏性文件覆盖与上下文静默截断。Cade 采用追加型不可篡改日志持久记录全量事件，配合磁盘快照池实现毫秒级原子回退。Rejecting destructive file overwrites and silent context truncation. Cade records full events into append-only immutable logs, backed by snapshot pooling for instant atomic reverts.

传统 AI 助手的撤销硬伤The Fatal Flaws of Legacy Undo Mechanisms

在现有许多编码助手或编辑器插件中，“撤销”往往只是在后续对话中告诉大模型“请撤销上一轮改动”。这种模式存在严重隐患：In many existing coding assistants, undo is merely an extra prompt asking the LLM to revert previous changes. This approach has critical drawbacks:

  • 二次幻觉风险：大模型撤销时可能写出与原代码略微不同的新代码，甚至破坏未保存的上下文；Secondary Hallucinations: The model often generates slightly different code when attempting to undo, frequently breaking surrounding untouched code;
  • Token 巨额浪费：把撤销代码与解释再完整输出一遍，凭空浪费数百上千 Token；Token Waste: Generating revert code and explanations burns hundreds of unnecessary tokens;
  • 磁盘脏数据残留：如果在工具运行中被强制中断，未完成的文件改动可能遗留在工程中，导致语法报错。Dirty State Residuals: Aborted file operations leave corrupted files on disk that break compilers and linters.

Cade 的无损快照与物理原子回退Deterministic Snapshot Pooling & Atomic Rollback

Cade 的设计核心在于物理确证性。当 Agent 调用任何写入类工具（如 replace_file_content、write_to_file）时：Cade enforces deterministic physical certainty. Whenever the agent calls any write tool (e.g. replace_file_content, write_to_file):

  1. 写前捕获（Pre-write Capture）：内核自动读取目标文件在修改前的完整字节流，压入不可变快照池（Snapshot Pool）；如果是新建文件，则标记其创建状态；Pre-write Capture: The runtime automatically records the unmodified file bytes into an immutable snapshot pool before touching the disk. Newly created files are flagged for deletion upon undo;
  2. 原子落盘：修改以原子事务方式写入文件系统；Atomic Write: Modifications are committed atomically to disk;
  3. 物理恢复 (/undo)：当开发者触发 /undo 时，系统直接从快照池恢复磁盘字节流，新建的文件被彻底物理删除，耗时仅需数毫秒；Physical Revert (/undo): When triggering /undo, the system restores pristine bytes from the snapshot pool and unlinks new files in milliseconds;
  4. 视窗指针回拨：运行时内核将活动对话历史的事件指针拨回上一轮，被撤销的交互不再输入给大模型。Window Pointer Rewind: The runtime rewinds the active event stream pointer, ensuring reverted turns never clutter future model contexts.

动态投影机制 (Dynamic Projections)Dynamic Projections Architecture

在 Cade 中，对话历史不是一个随意可编辑的列表，而是一个不可变追加型事件流（Append-only Event Log）。当前发送给模型的 Prompt、TUI 的对话视窗以及 Web 看板，仅仅是该事件流的不同投影视角（Projections）：In Cade, conversation history is not a mutable array, but an append-only immutable event stream. The model prompt, TUI split-panes, and Web views are purely deterministic projections derived from this stream:

会话分支能力 (/fork)Session Branching (/fork)

得益于无损事件流，你可以随时使用 /fork 基于历史中的某一个特定节点创建一条新的探索分支，原会话的历史与快照树不受任何污染，便于进行平行技术方案对比。Thanks to lossless event logging, you can run /fork at any turn to create an independent exploration branch without corrupting the parent timeline, ideal for testing alternative architectural approaches.

核心支柱 2：95% 无摘要换窗机制Core Pillar 2: 95% Summary-Free Context Rollover

告别递归自我总结带来的严重失真。在 95% 模型上下文容量阈值自动平滑重开窗口，继承任务目标与约束，中间工具冗余安全对冲。Eliminating compounding distortions from heuristic recursive summaries. Smoothly rolls over context at 95% capacity, inheriting task goals while pruning intermediate tool dumps.

为什么递归总结（Recursive Summary）是代码工程的毒药？Why Heuristic Recursive Summarization Destroys Codebases

主流 AI 编程工具在上下文即将填满时，通常命令模型“将前面的消息总结为一段摘要”。然而在真实软件工程中，这会导致灾难性的信息坍塌：When context fills up, most AI tools prompt the LLM to summarize previous messages. In real-world software engineering, this causes catastrophic degradation:

  • 精密坐标彻底丢失：行号范围（如 Line 142-188）、正则捕获组、精确类型签名在摘要中必定被高度概括，后续工具调用精准度归零；Loss of Precision Coordinates: Exact line numbers, regex groups, and strict type signatures are lost in summaries, crippling subsequent patch accuracy;
  • 幻觉自我强化循环：一旦某次总结中模型微调了对业务逻辑的推测，该推测就会在后续窗口中被当作“铁定事实”继续衍生，导致越改越偏；Compounding Hallucinations: If the model makes a minor incorrect assumption during summarization, that assumption becomes ground truth in future windows, driving refactors further off track;
  • 严重的 Token 与时间损耗：生成数千 Token 的摘要耗时极长，且消耗大量昂贵的输出配额。Latency & Cost Spikes: Generating multi-thousand token summaries introduces major latency and burns expensive generation quotas.

Cade 95% 平滑换窗的数学与执行模型Cade 95% Rollover: Mathematical & Algorithmic Model

Cade 采用严格的上下文预算监控器。内核在每一次模型推理前精确统计当前 Token 占用：Cade applies a strict context budget monitor that recalculates total tokens before each inference cycle:

Formula 
CurrentRatio = (PromptTokens + SystemPromptTokens) / ModelContextWindowLimit

if CurrentRatio >= 0.95:
    trigger_context_rollover()

换窗时的四步确定性对冲流程Four-Step Deterministic Rollover Lifecycle

  1. 目标与约束完整继承（Target Retention）：保留最初的用户核心需求指令、当前目标与关键约束；Goal & Constraint Retention: The original user objective, current goal, and key constraints carry over completely;
  2. 中间工具冗余安全对冲（Tool Output Pruning）：已执行完成的巨量中间输出（如搜索返回的 800 行代码片段、长文本目录树）被剥离活动视窗，仅保留执行结论；Intermediate Output Pruning: Bulky intermediate payloads (e.g. 800-line search dumps and directory scans) are purged from active view, retaining only operation statuses;
  3. 按需读取原始历史：新窗口可通过 history 工具定位原始证据；Memory 不随换窗自动保存或加载；History on Demand: The new window can use history tools to locate original evidence; rollover does not automatically save or load Memory;
  4. 新视窗平滑接力：开发者无感继续交互，模型拥有充沛的新窗口容量推进复杂工程重构。Seamless Window Handoff: The developer continues the conversation without interruption, while the LLM gains fresh token headspace.

换窗参数配置 (Configuration)Rollover Configuration

你可以在项目 cade.config.json 或全局 ~/.cade/settings.json 中调整换窗阈值：Tune the rollover threshold in cade.config.json or ~/.cade/settings.json:

JSON

  "agent": {

  }

核心支柱 3：按需 MemoryCore Pillar 3: On-Demand Memory

范围与职责Scope and Responsibilities

只保存当前 workspace 的经验。Repository/Git/Tests 判定当前事实，Event History 保存完整历史，NOTE.md 保存任务状态，Skills 保存可复用方法。Memory is scoped to the current workspace. Repository/Git/Tests establish current facts, Event History preserves history, NOTE.md holds task state, and Skills hold reusable methods.

权限审查与沙箱安全体系Permissions, Security & Sandboxing

面向开发机环境的多道防线防御。最小权限原则、工作区路径边界隔离与敏感凭据脱敏审计。Defense-in-depth architecture protecting developer machines. Principle of least privilege, workspace path jailing, and audited credential redaction.

四层深度防御体系Four Layers of Defense-in-Depth

防线 1：工作区路径隔离Layer 1: Path Jailing Path Jail

严格限定 Agent 仅能在当前工程工作区及其明确指定的子目录下进行读写。任何尝试向上穿越（如 ../../etc/passwd）或访问 ~/.ssh/ 的调用直接被内核硬阻断。Restricts the agent exclusively to the active repository workspace. Path traversal attempts (e.g. ../../etc/passwd) and sensitive targets (~/.ssh/) are hard-blocked.

防线 2：策略引擎动态匹配Layer 2: Policy Gating PermissionEngine

内核维护细粒度的权限规则表。可根据工具名称、文件模式、Shell 命令内容动态判定：直接放行（Allow）、直接拒绝（Deny）或必须经过人工确认（Prompt）。Maintains fine-grained policy rules evaluating tool names, file patterns, and shell commands: auto-allow, auto-deny, or mandatory human confirmation.

防线 3：Linux 容器沙箱Layer 3: Bubblewrap Sandbox Linux Sandbox

在 Linux 环境下，Agent 的 Shell 子进程默认在轻量级 bubblewrap 容器沙箱中运行：隔离宿主根目录只读挂载、独立网络命名空间、只允许工作区与临时目录读写。On Linux, agent shell commands run inside a lightweight bubblewrap sandbox: read-only host mount, network namespace isolation, and ephemeral scratch areas.

防线 4：脱敏审计持久化Layer 4: Redacted Audit Logs Audit Trail

所有操作与工具输出持久化记录在 audit.jsonl 中。内核自动对 API Key、Bearer Token、密码和敏感凭据进行正则脱敏，防止凭据泄露。All interactions persist to audit.jsonl. Credential patterns (API keys, passwords, bearer tokens) are automatically redacted before logging.

编写一个 SKILL.mdAuthoring a SKILL.md

SKILL.md Template 
---
name: refactor-clean-code
description: 专门用于业务模块分层解耦与单测补全的工程规范指南。description: Specialized engineering guidelines for module decoupling and unit tests.
tools_allowed: [view_file, replace_file_content, run_command]
version: 1.0.0
---

# 核心重构不变量
1. 单个 Python 文件函数不得超过 40 行，模块不得超过 300 行；
2. 严禁出现未标注类型的函数入参和返回值；
3. 任何重构修改落地后，必须调用 run_command 执行 `pytest tests/` 确保零回归；
4. 业务代码与 I/O 隔离，禁止在领域实体中直接发起网络请求。# Core Refactoring Invariants
1. Functions must not exceed 40 lines; modules must not exceed 300 lines;
2. All function parameters and return types must have explicit type annotations;
3. Always execute `pytest tests/` via run_command to verify zero regressions;
4. Enforce strict I/O separation; never issue network requests within domain entities.

Subagents 多代理并行编排Subagents Parallel Orchestration

将庞大复杂的长程研发任务拆解。在独立且干净的上下文视窗中派生子代理并行推进，极大保护主干上下文预算。Deconstruct complex engineering tasks into isolated sub-tasks. Spawn autonomous subagents with clean context windows to protect the primary context budget.

为什么需要子代理编排？Why Subagent Orchestration Matters

在重构大型工程时，主 Agent 如果直接对全库数十个文件进行搜索与扫描，会瞬间把宝贵的上下文窗口塞满代码噪声。通过派生专属的子代理（Subagents）：Scanning dozens of files in a massive repository quickly exhausts context budgets with inspection noise. Delegating to specialized subagents solves this fundamentally:

  • 干净的上下文隔离：子代理在独立进程中运行自己的推理循环，拥有独立的 Prompt 预算；Isolated Context Sandboxes: Subagents execute within independent loops, consuming their own fresh token budgets;
  • 成果精简归纳回传：子代理完成深度勘察或密集测试后，仅向主规划 Agent 返回精炼的结论字典，主干上下文消耗趋近于零；Synthesized Return Payloads: After extensive exploration, subagents return structured summaries, saving thousands of tokens for the parent agent;
  • 角色专精：可针对调研（Research）、测试（Testing）、文档生成分别配置最适宜的轻量模型或大模型。Specialized Roles: Configure specialized subagents (researchers, test runners, reviewers) with distinct prompts and cost-efficient models.

生命周期 Hooks 拦截机制Lifecycle Hooks & Event Interceptors

在会话启动、工具调用前后与模型响应周期中挂载确定性的自定义 Python 钩子脚本，实现格式化、安全核验与审计集成。Attach deterministic Python hooks at session bootstrap, before/after tool runs, and during inference cycles for linting, security gating, and telemetry.

可用的生命周期钩子事件Supported Lifecycle Hook Events

Hook 事件名称Hook Event 触发时机与调用参数Trigger Timing & Parameters 典型用途与拦截行为Typical Use Cases & Action
on_session_start 会话创建或断点续接时触发。传入 session_id, cwd。Triggered when a session is initialized or resumed. Receives session_id, cwd. 环境健全性检查、拉取 Git 分支最新状态、清理陈旧临时文件。Verify environment health, git sync check, clean up stale temporary files.
pre_tool_call 任何工具执行前触发。传入 tool_name, arguments。Triggered right before executing a tool. Receives tool_name, arguments. 动态参数校验与敏感路径二次阻断。抛出异常或返回非零状态码可直接中止工具执行。Validate parameters and block sensitive file paths. Returning non-zero aborts tool execution.
post_tool_call 工具执行完毕后触发。传入 tool_name, result。Triggered immediately after a tool finishes. Receives tool_name, result. 代码修改后自动运行 ruff format / eslint 格式化，或触发测试套件。Auto-run ruff format after edits, execute linting, or run unit tests.
on_session_end 开发者退出会话时触发。传入 summary, event_count。Triggered when exiting Cade. Receives summary, event_count. 自动生成会话归档报告、发送 Slack/钉钉团队进度通知。Generate session report, notify team chat channels, clean sandbox containers.

编写一个实战 Hook (.cade/hooks/post_edit.py)Writing a Custom Hook

在项目中创建 .cade/hooks/post_edit.py 脚本：Create a custom hook script at .cade/hooks/post_edit.py:

Python 
import subprocess, sys

def post_tool_call(tool_name: str, args: dict, result: dict):
    # 当执行文件写入工具时，自动格式化修改过的文件Auto-format files modified by write tools
    if tool_name in ("replace_file_content", "write_to_file"):
        path = args.get("TargetFile")
        if path and path.endswith(".py"):
            subprocess.run(["ruff", "format", path], check=False)
            print(f"[Hook] Auto-formatted {path} via ruff")

高效特殊指令语法Special Command Syntax & Shortcuts

CLI 模式支持多项加速日常输入的快捷前缀：The CLI interface provides powerful input prefixes for daily speed:

  • @ 引用精准文件：在输入中加入 @src/cade/main.py，内核会自动读取并将其精准嵌入提示词，无需模型进行额外探测；@ File Ingestion: Mentioning @src/cade/main.py reads and embeds file bytes directly into prompt context;
  • ! 原生 Shell 直达：以感叹号开头（如 !git status 或 !pytest）直接在本地 Shell 执行命令并展示输出，不消耗大模型 Token；! Raw Shell Escape: Starting with an exclamation mark (e.g. !git status) executes commands directly on host without consuming LLM tokens;
  • / Slash 指令执行：直接键入 /undo、/plan、/act 操控会话；/ Slash Commands: Execute /undo, /plan, /act directly;
  • Shift+Enter 多行换行：输入多行长需求或粘贴代码段时保持完整排版。Shift+Enter Multi-line: Input multi-line requirements or paste code blocks without premature submission.
