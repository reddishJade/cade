# 会话管理、快照回滚与上下文换窗

在长时间的复杂编码任务中，模型往往会面临两大难题：**上下文窗口爆满**与**代码改错难以挽回**。

Cade 通过**事实账本持久化**、**文件级快照回滚**与**无摘要换窗机制**，从工程层面彻底化解了这些痛点。

---

## 1. 会话持久化与状态存储

Cade 的状态设计遵循 **“状态即事件日志的投影”**。

- 每次交互、每条用户指令、模型推理 Envelope 以及每一次工具执行的输入与输出，都会实时以追加写（Append-only）的方式落盘至：
  ```text
  .cade/sessions/<session_id>.jsonl
  ```
- **关机不丢进度**：即使终端意外关闭或系统崩溃，已执行的步骤全部完好记录；
- **无缝恢复**：再次打开终端运行 `cade`，输入 `/continue` 即可从上一轮中断的地方继续推进，或者使用 `/sessions` 挑选并恢复任意历史会话。

---

## 2. 秒级快照撤销：`/undo` 与 `/rewind`

很多开发者对 Agent 改代码感到担忧：一旦 Agent 批量改动了 5 个文件，改坏了怎么撤回？

### 2.1 文件级修改秒级撤回 (`/undo`)

Cade 在执行任何文件修改类工具（`write`、`edit`、`patch`）之前，都会自动捕获被修改文件的原始内容，生成轻量级的**变更前快照（Snapshot）**。

- 如果 Agent 最近一次的代码修改有误，你只需输入：
  ```text
  > /undo
  已撤销最近 1 次工具执行产生的文件变更（共还原 2 个文件）。
  ```
- `/undo 3` 则可以一口气回滚最近 3 次工具操作对应的所有文件变动。
- 这是一种精确到文件字节级的确定性物理回滚，完全不依赖 Git 暂存区，也不会影响你工作区中尚未提交的其他更改。

### 2.2 对话历史回退 (`/rewind`)

如果你发现自己前两轮的 Prompt 提示词引导偏离了方向，希望 Agent 忘掉最近的几轮对话：

```text
> /rewind 2
```

当前会话将回退到 2 轮对话之前的上下文状态，方便你重新组织语言发起提示。

---

## 3. 上下文换窗（Rollover）：告别递归总结与幻觉

在传统的 Coding Agent 中，长上下文通常采用“LLM 自动总结历史（Compactor）”的方式压缩。然而在真实工程实践中，**让模型压缩代码对话会丢失关键的文件路径、函数签名和测试命令，极易引发灾难性的幻觉**。

Cade 采取了更具确定性的 **无摘要换窗（Summary-free Rollover）** 机制：

### 3.1 运作机制

1. **95% 水位线监控**：系统持续监测当前窗口已占用的 Token。当达到设定比例（默认 `rollover_trigger_ratio = 0.95`）时，系统判定当前上下文即将耗尽。
2. **NOTE.md 任务交接**：Cade 提示或自动将当前的任务进展、关键架构决策以及待办事项沉淀至项目根目录的 `NOTE.md`（Working Note）中。
3. **干净窗口重置**：Cade 直接丢弃冗长的旧上下文窗口，重置为一个**完全干净的新上下文窗口**。
4. **状态无损衔接**：新窗口启动时，会自动将系统 Prompt、项目结构以及刚才整理的 `NOTE.md` 作为前置上下文读入，继续推进未竟工作。
5. **历史可回溯**：旧窗口中的所有原始工具输出依然保存在 `.cade/sessions/` 的 JSONL 账本中，模型随时可以通过查询历史指令检索早前的关键事实。

### 3.2 手动换窗操作

如果你感觉当前对话轮次过多、注意力分散，也可以在终端随时主动发起换窗：

```text
> /rollover
已将当前工作状态同步至 NOTE.md，并开启干净的上下文窗口。
```
输入 `/context` 可随时查看当前窗口的 Token 预算与换窗余量。
